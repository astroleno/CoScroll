## 数据与处理

- 来源为 `Character/_remaining71_v2_1mb_20261022/delivery/` 的 71 个文件和
  `Character/_iteration4_1mb_20261022/delivery/` 的 4 个文件。分别与该批 `FINAL_REVIEW.json`
  的最终 APPROVED 记录、原始模型摘要及同一文件的浏览器验收记录匹配。
- 75 个 GLB 合计 **69,994,860 字节**，每个 **649,364–939,416 字节**，均小于 1,000,000 字节。
- 使用已验收的几何版本；本次入库不再减面或改变模型坐标。每个文件包含一个静态 Mesh，节点变换为单位矩阵。
- 17 个模型含稀疏 `TEXCOORD_1` 和对应的零值 `TEXCOORD_0`。这些数据维持既有平滑算法中的顶点区分，
  必须连同几何保留，不能以“未使用的贴图坐标”为由删除。测试按三角形顺序核对完整 UV 数据。
- 沿用项目完整精度的基础层/外层预处理及加载回退，参数仍为
  `outerOffset=.001`、`maxEdge=.15`、`subdivisions=0`、`creaseAngle=30`、平滑着色。
- 26 份旧 OBJ 及其已提交的预处理文件保留原字节。不同 Node / 浏览器压缩库可生成不同 gzip 字节流；
  编码测试核对解压后的完整数据及元信息，源文件和实际交付载荷仍分别校验 SHA-256。

原始 GLB 的 1 MB 上限只描述该文件。预处理 JSON 包含基础层与外层，体积另计；
不能把 GLB 大小当成网络、CPU 或 GPU 内存预算。项目仍按当前字和临近字加载，
已有曲目配置及映射继续使用相同路径。

75 份预处理 JSON 合计 **166,214,996 字节**，单份 **1,414,852–2,621,930 字节**；
连同原 26 份，整个预处理目录为 **190,676,764 字节**。这是完整 JSON 大小，
不等于后续发布时经 HTTP gzip 压缩的传输量，也不等于运行时几何内存。

## 验证依据与边界

原始 GLB 的坐标、索引、UV 与部件由独立的二进制读取获得，未借用项目 GLTFLoader 或预处理算法。
外层数量与此前同一文件摘要的实际双层浏览器验收记录核对。
运行时回归覆盖全部 75 个模型的正常预处理加载、损坏载荷回退、无原生解压能力回退，
并保留全部 26 个旧模型的独立完整几何基线和自定义外层参数校验。
实际 101 个模型的缓存遍历检查活跃模型保留、最多 8 个闲置项，以及每个被淘汰模型的两层几何各释放一次。
最后保留的 8 对几何仍可使用；测试结束时单独清理。旧 `ModelPreloader.clearCache()` 只清索引，
当前生产代码不调用它，不能用该方法验证几何释放。

生产构建的本地页面另检查了七个现用字：390 × 844、DPR 2 的桌面 Chromium 手机视口中，
每字都核对了实际场景的完整三角形坐标摘要，确认双层材质与贴图就绪，并连续旋转超过一整圈。
七张正面截图均检查了字形及表面，未见新增明显缺笔或破面；浏览器运行错误为 0，
