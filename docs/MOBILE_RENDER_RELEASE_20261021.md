[完整模型预计算与公网复测](MODEL_PRECOMPUTE_RELEASE_20261021.md)。本报告保留上一阶段的实现与测量记录。

## 实现与画面

- 丝绸背景显式关闭抗锯齿、深度和模板缓冲，平面关闭深度测试/写入；背景组件 memo。
- 新内部 `specializePhysicalMaterial` 通过 Three 公共编译钩子，将生命周期内固定的
  roughness、metalness、IOR、transmission、thickness、opacity、specularIntensity、
  diffuse、emissive、specularColor 和正面材质的 normalScale 编译成 float32 常量。
- 保留原有物理着色公式、贴图、采样和 Three 原生透射流程；环境强度继续使用动态 uniform。
  参数变化仍重建材质，程序缓存身份包含所有固定值。双面材质不固定 normalScale，
  保留 Three 绘制背面时翻转它的行为；无穷/NaN 保留 uniform。
- 替换或卸载玉石材质时 dispose；独立拥有的纹理继续按原有生命周期释放。
  ego-lite 记录 console.error，避免将着色器编译失败误当成成功画面。

两画布、DPR、原丝绸 shader、玉石双层、完整字体和交互接口均保留。
390×844、DPR 2 时，背景仍为 780×1688，正文为 702×1288。
完整 WOFF2 仍为 2,447,968 字节，SHA-256 为
`76e1269db23aa03c8515da4a937bc5a2cb437db3caf65bf3a0fe7b7b26a57af6`。

固定场景将背景时间设为 1.25，并恢复旧版的歌词位置、透明度、羽化和模型角度。
本地背景逐像素一致，三个玉石角度（0、π/2、π）至少 99.999% 像素一致，最大通道差 3/255；
最终公网四张画布图与旧版参考逐像素一致。内/外层顶点数仍为 12,170 / 19,252。
实际背景上下文的 antialias/depth/stencil 为 false；Three r160 仍报告 alpha=true，
没有将其计作已消除的透明通道。

## 性能结果与限制

ego-lite Chromium / Apple M4，手机视口 390×844、DPR 2、Android UA、焦点模拟。
正文约 6 秒，封面约 3 秒；浏览器缓存禁用，但未清空系统字体、V8、GPU 或 CDN 缓存。
共享机器负载在调查期间显著波动，公网测量时没有并发的本任务构建或文件下载校验。
以下均不是 Android/iOS 真机成绩，也不代表标准冷启动。

| 本地相同测试设置 | 旧版 | 新版 |
| --- | ---: | ---: |
| 正文 FPS | 27.73 | 27.12 |
| 正文 p95 帧间隔 | 49.9 ms | 50.0 ms |
| 正文 R3F React 提交次数 | 46 | 23 |
| 4 倍 CPU、4 Mbps 下载/1 Mbps 上传、80 ms 延迟：正文 FPS | 22.98 | 22.89 |

| 新版公网样本 | FPS | p95 帧间隔 |
| --- | ---: | ---: |
| 正常竖屏，首次播放 | 27.22 | 50.0 ms |
| 正常竖屏，超时恢复后的独立样本 | 27.78 | 49.1 ms |
| 4 倍 CPU、4 Mbps/1 Mbps、80 ms，首次播放 | 8.13 | 1,032 ms |
| 相同压力，模型/材质/文字已经加载后的续播 | 25.00 | 34.3 ms |
| 桌面 1440×900、DPR 1 | 27.75 | 34.4 ms |

正常公网观测到字体 5.74 秒、音频 8.24 秒就绪；压力样本分别为 13.97 / 11.84 秒。
正常竖屏正文文字 Canvas 上传为 0，桌面窗口内容变化时上传 1 次。
R3F 更新约减半是确定的工作量下降；同版本首次播放与已加载续播的差异不能当成优化收益。
压力下仍有明显长停顿，不能宣称手机已流畅或稳定 60 FPS。
最后恢复正常 CPU/网络，导航到空白页并丢弃三次动画回调后采样 6 秒，
得到 60.17 FPS、p95 17.4 ms；这只是同环境额外对照，不是手机性能成绩。

正常公网 GPU 查询的主画布平均为 6.05 ms，背景 1.01 ms；这不是独立环境下的前后基准。
同一固定场景还进行了原生材质/常量材质的交替测量：平衡奇偶帧的两组主画布均值分别为
8.35→9.41 ms、13.25→12.60 ms，没有稳定方向。
早期原型的 13.66→12.25 ms（约 10%）未得到复现，不作为最终收益。
进一步的饱和粗糙度展开同样没有稳定收益，未纳入正式包。
临时对照材质销毁后，主画布程序数量回到 4，几何和纹理计数回到测试前值。

CPU 采样的热点包括 OBJ parse、mergeVertices、loadModelFromFile、createOffsetGeometry。
对应现有 ModelPreloader 的同步解析、顶点合并、法线和外层几何处理；材质常量化没有移走这部分工作。
这提供了下一步方向，尚不能把所有停顿都归因于某一个函数。

## 交互与失败记录

公网 390/360 竖屏原生触摸通过：开始、播放/暂停、双向 180 px 横滑各 ±15 秒、
0→359.256327 秒回绕、进度拖动、快速往返与续播；无 pointercancel、无横向溢出。
连续输入 2、9、3、8、4、7 秒后，音频和进度条均稳定在 7 秒。
封面与正文保持同一背景 Canvas，共两个画布。
桌面 Enter、Home、左右方向键及 Shift 组合、鼠标拖动、双向横拖、纵向滚轮、
正反横向滚轮和续播均通过，非拖动移出滑条没有回退进度。
按实际收到的滚轮事件验证（工具发出 180 时 DOM 为 360），没有误用输入值。

独立压力诊断有一次 CDN 核心脚本请求超时，导致 ChunkLoadError 和 React 恢复错误；
未计作成功验收。恢复后，在真实浏览器重新下载该 667,913 字节脚本并核对 SHA-256：
`a0b5188ec44fba9bec574076bbb0219597b5b6a2d0d58c4738086ae2ca87d3b1`，
随后页面正常重载、播放和已加载压力测试通过。不能据此保证网络永远稳定。
一个诊断观察器脚本还出现了语法错误，后续检查确认属于测试注入代码，未进入产品或发布包。
成功的正常、压力、触摸和桌面验收样本没有应用错误。

## 尚待确认的模型优化方向

当前帧率目标仍未达标。下一步建议提前生成全部现有 OBJ 模型的完整默认几何数据，
在 ModelPreloader 增加读取预计算数据的路径，并预填充默认外层几何缓存。
模型不减面，位置、法线、UV、索引使用可逐字节核对的完整数据；两画布、材质、贴图、字体和手势保留。
loadModel/getOffsetGeometry 及项目配置接口保持原签名；自定义模型/非默认几何参数保留原算法。
涉及共享几何处理模块、生成工具、模型数据和加载路径，超出本轮已确认的背景/材质方案，尚未实施。
需先确认架构，再验证全部模型属性字节等价、多角度画面、首次加载/换模型长任务、
正常与压力帧率、原有参数分支和公网交互；通过后再发布和提交。
