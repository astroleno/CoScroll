# 手机加载、转经轮与公网验收（2026-10-22）

本轮沿用 `decoupled`，公开版本为 `coscroll-995562e8da979533`。
修复快速触摸输入和抬手冲量，移除公开「画面」入口，缩短启动的串行等待并减少正文协调工作。
持续帧率仍约 30 FPS，压力下偶发长帧尚未根治；没有把这轮描述成稳定 60 FPS。

## 变更与原因

- 构建时将目录内两首经过校验的配置及原 LRC 写入当前 release 的 HTML；客户端仍走
  原配置校验器和 LRC 解析，损坏提示、缺失数据、强制刷新走原 HTTP 路径。
- 提前请求完整主字体、所选完整初始模型和录音 HEAD。正式 AudioEngine 复用已经离线
  核实的录音时长，随后由原生 metadata 校正，不再另建临时 Audio 下载同一录音。
  去掉首次 DOM `src` 已开始加载后紧接着的重复 `load()`。
- 初始脚本标签从 17 个减到 7 个，Brotli 总量约 340,415 → 332,633 字节，
  没有通过删除渲染功能缩包。慢网下同时抢载约 2.5 MB 贴图的中间候选退化到约 16 秒，
  已调整为完整字体就绪后再提示贴图；两张贴图及原材质流程不变。
- 有连续时间引用时，音频时间通知不再让整个 Canvas 重新协调；结构、播放状态、seek、
  字体、锚字和视口变化仍然生效。已就绪字体不再触发整窗文字的重复栅格化和上传。
- 正文采用非 passive、capture 阶段的原生 TouchEvents，鼠标/笔继续用 PointerEvents。
  速度直接供 Three 帧循环读取；触摸的速度变化不再误触发前后台降速。
- 新回归复现了用户所述「一滑没反应」的一种具体路径：一次合并移动后马上抬手，
  在下一绘制帧之前速度就被清零。现在经文/媒体在松手时准确提交终点，玉字冲量独立保留
  并衰减；取消、新 seek 和切曲清理旧输入。原 12 px/s、双向跨轮及所有控制入口保留。
- 公开界面只保留经典切换；仍解析各曲配置和本机既有色系选择，不提供调色面板。

## 性能

本机、同一 ego-lite 的 390×844 / DPR 2、禁用浏览器 HTTP 缓存；正常 CPU 1 倍，压力
CPU 4 倍、4 Mbps 下行 / 1 Mbps 上行、80 ms 延迟。保留字体、V8、GPU 与 CDN 缓存，
不称作全新设备的标准冷启动。每种正文条件 6×10 秒，FPS 按总帧数/总时长计算，
p95 是各十秒片段的范围，不能当作合并样本的 p95。

| 本地对照 | 原版妙法 | 最终妙法 | 最终心经 |
| --- | ---: | ---: | ---: |
| 正常 60 秒 FPS | 29.572 | 29.614 | 29.638 |
| 压力 60 秒 FPS | 28.228 | 29.578 | 28.875 |
| 正常最大帧间隔 ms | 51.0 | 50.9 | 51.1 |
| 压力最大帧间隔 ms | 1,049.1 | 51.8 | 1,050.5 |
| 正常 R3F React 提交 / 60 秒 | 261 | 36 | 31 |
| 压力 R3F React 提交 / 60 秒 | 264 | 37 | 33 |

可重复确认的是场景协调次数减少约 86%，不是稳定 FPS 大幅上升。最终心经压力中仍记录
一段超过 500 ms 的长帧；中间候选的妙法压力也出现过。部分 LoAF 的 blockingDuration=0、
scripts 为空，没有同量级 JS 长任务；不足以把完整原因归结为 React、GPU、设备或浏览器。
GPU 查询在单独窗口采集，不声称覆盖了每一次长帧。

本地无压缩预览的音频有数据时间约 1.25 → 0.97 秒；压力约 11.15 → 11.12 秒，基本相同；
压力首个背景绘制约 5.37 → 8.14 秒，该指标退化。因此公网单独对照 CDN 实际压缩和请求排队，
不拿本地正常网的亚秒成绩宣传手机首载。多 face 字体的旧计时可能先记录补字字体，
新测量额外检查「心经」用字的主字体状态；封面与原生音频条件用于相同口径对照。

公网独立复测在完整资源 HTTP 校验结束后进行，避免同时下载约 100 MB 文件干扰测量。
同一妙法 URL、同一环境，各一次对照的音频有数据时间：正常 13.28 → 11.64 秒，
压力 15.25 → 13.74 秒；封面就绪分别 10.69 → 10.84 秒、12.50 → 12.62 秒，未改善。
这些是有限样本，不能表述为稳定低于 10 秒。

公网正文正常 / 压力各 60 秒均为 29.05 / 29.06 FPS，R3F 提交 37 / 36 次，
最大帧间隔 52.1 / 1,049.6 ms，运行错误均为 0。公网压力下也保留了一次约一秒长帧。

为核对网络波动，另作两次正常导航并保留完整 Navigation/Resource Timing：
Tongye 的封面 / 音频 / 首个背景绘制为 6.56 / 7.36 / 7.74 秒；Aitoshuu 为
12.24 / 13.14 / 13.51 秒。导航开始至 HTML 首字节分别为 2.23 / 7.03 秒；
发出 HTML 请求到首字节约 0.40 / 0.45 秒，其余主要在连接建立及请求排队之前。
不能把这部分连接及网络等待全部归因于模型或字体。这两次额外样本都列出，
没有只挑 7.36 秒替代独立对照的 11.64 秒。完整字体及初始模型依然影响 HTML 到达后的等待，
本轮不能宣称所有手机网络下都能快速首载。

公网独立 GPU 查询的背景 / 正文平均约 0.5 / 4.5 ms，属于这台电脑的测量，
不足以代表 iPhone GPU。约 993 ms 的压力长动画帧没有归因脚本及同量级 JS 长任务；
仍需要真实设备的浏览器、合成、GPU 与网络记录查明余下停顿。
