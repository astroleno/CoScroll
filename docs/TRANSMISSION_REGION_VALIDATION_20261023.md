日期：2026-10-23。范围：按已确认的区域更新方案实现，保持当前画质和双 Canvas，验证全部正式字模并比较性能。后续用户要求收尾、清理临时资料并 commit/push；没有部署。

## 实现

- 在 Three 完成场景矩阵和可见对象列表更新后，投影内层字模包围盒的 8 个角，合并上一帧和本帧范围，并外扩 3 个实际绘制像素。
- 保留完整透射纹理、HalfFloat、4 samples、完整原生 mipmap，以及现有材质、几何、HDR、法线、背景、歌词和整层遮罩。主 Canvas 的 DPR 上限仍为 1.8，背景仍为 2。
- 只对必要区域执行清除和多重采样解析。清除后立即关闭 scissor；已验证的几何本身就在该区域内，绘制不需要重复应用区域裁剪。这一步去掉了初版区域实现额外的绘制状态成本。
- 包围矩形、矩阵和历史状态一次分配后复用；帧循环没有新增同步 GL 状态读取、数组或向量分配。缺少包围盒的旧字模仅在加载时补算一次，不修改顶点或资产文件。
- 首次使用、尺寸或相机改变、模型/材质实例或材质编译版本改变、context 恢复，先执行完整更新。不能证明覆盖的场景继续走原始路径，包括额外不透明对象、透视相机、变形几何、双面透射、特殊背景、XR、自定义目标及不支持的 MSAA 路径。
- 通过构建时的版本与源码 SHA-256 检查适配 Three 0.160.1，生成独立模块并让应用和 R3F 使用同一实例；没有持久修改 `node_modules`。升级 Three 时会明确阻止未经复核的适配。

相关文件：`src/rendering/transmissionUpdateRegion.ts`、`src/rendering/TransmissionRegionRendering.tsx`、`deploy/three-transmission-region.mjs`，以及主场景和字模加载器的生命周期接入。

## 验证方法

数据来自当前仓库、上述本地产物和独立 Chrome for Testing 156.0.8078.47。GPU 为 Apple M4 / ANGLE Metal。可见 Chrome 的呈现追踪与无界面 Chrome 的自动功能/GPU验证分开记录；无界面结果不作为真实屏幕呈现帧率。

手机布局显式设置 iPhone UA 和 390 × 844 CSS px，主场景实际绘制 702 × 1288，背景 780 × 1688。桌面布局为 1300 × 1000 CSS px，主场景 2340 × 1569，背景 2600 × 2000。这些都是本机 Chrome 测试，没有模拟真实手机 GPU。

原始路径通过禁用可选区域 provider 获得；GPU 对照在同一最终构建内完成。固定“化”字场景，每窗重置模型角度，背景继续按产品逻辑运动。每个布局采用 A/B、B/A、A/B 三组配对，每个采样窗口 30 秒，切换后先预热。GPU 记录 `EXT_disjoint_timer_query_webgl2`；失效查询和转后台窗口不能用于验收。

逐像素回归使用真实生产场景与正式预处理几何，依次比较 101 个字模。每个字模包含 11 个连续姿态：正面、侧面、背面、任意角度、快速反向和左右视口边缘。比较的是包含模型与歌词的主 Canvas RGBA；同时核对区域路径确实执行，而非一直回退完整更新。

## 最终结果

| 指标 | 原始路径 | 区域更新 | 结果 |
| --- | ---: | ---: | --- |
| 手机布局主画布 GPU 平均耗时 | 6.203 ms | 4.828 ms | 降低 22.2% |
| 桌面布局主画布 GPU 平均耗时 | 13.724 ms | 9.695 ms | 降低 29.4% |
| CPU 交错微基准平均耗时 | 0.3655 ms | 0.3663 ms | 差值 0.0008 ms |
| CPU 交错微基准 P95 | 0.700 ms | 0.700 ms | 相同 |

GPU 均值来自最终版本每路、每布局 5,400 个有效查询；无 disjoint。补充的相邻帧交错对照中，手机布局 GPU 中位数为 4.431 → 3.028 ms、P95 为 10.625 → 8.141 ms；桌面布局中位数为 12.991 → 6.816 ms、P95 为 24.516 → 12.842 ms。两种采样方法都显示改善，主表采用较保守的长窗口结果。

CPU 微基准每路 600 帧，两路均执行包围盒计算以保持交错过程一致。该计算单独测量 100,000 次合计 21.3 ms，约 0.00021 ms/次，新增同步 GL 状态读取为零。结果支持原型的显著 CPU 回退已消除，不能证明所有设备上的绝对零开销。

- **画质：**101 个正式字模 × 2 个布局 × 11 个姿态，共 2,222 次比较，变化像素为 0；每个字模都实际执行了区域路径，GL 错误为 0。
- **功能：**三次尺寸切换、三组调色、context 恢复后的原始路径对照均通过。两首内容的触摸、滚轮、正反向命令、最新手势优先、受控前后台恢复均通过；每首完成三次 16 倍速自然循环，循环过程没有写入 seek，并验证 1 倍速边界。
- **资源：**四次内容切换复用 HDR、法线与材质，没有新增纹理请求；结束时仍为两个 Canvas。
- **自动检查：**72 项运行测试、11 项打包测试通过；产品源码快照的类型检查与生产构建通过。
- **呈现追踪：**前一候选 r2 的正常播放、快速交互各 60 秒可见窗口对照约为 60 FPS，无长任务或长帧。最终 r3 的补录发生 `Runtime.evaluate` 超时，未取得有效追踪；不能把 r2 或无界面的帧率作为最终版屏幕呈现验收。

## 验证边界与已知问题

1. **真实 iPhone/Safari、Android/Chrome 及最终版可见窗口呈现追踪尚未完成。** 本机硬件加速 Chrome 的结果不能替代真机功耗、温度和驱动表现。用户要求在现有结果上收尾，未继续扩展测试。
2. **强制 context 恢复存在原有色差。** 禁用区域更新后，同样能复现恢复前后的颜色变化；同一个恢复状态下，原始与最终区域路径逐像素一致。区域更新的恢复和全幅初始化没有新增差异，但“恢复前后绝对画质一致”仍有这个既有缺口。
3. **工作区存在既有类型错误。** 未受管审阅工具 `src/utils/performanceDiagnostics.ts:182` 引用了未定义的 `slowResources`。没有改动该文件。本次构建使用当前受管产品源码和新增渲染文件的普通目录快照，排除这个无关工具；快照生产构建包含正常类型检查并已通过。
4. Three 适配有明确版本边界；不满足优化条件时保持完整渲染。GPU 数字是实际命令区间耗时，受频率和共享 GPU 负载影响，不等于 GPU 核心利用率，也不能直接换算为 FPS 增幅。
