# 手机首载与一秒长帧：第三轮验收

日期：2026-10-22 至 2026-10-23。状态：已发布两站，HTTP/ego-lite 验收通过；长帧及真机限制见下文。

## 范围与实现

按用户确认的 [本轮方案](MOBILE_BOOT_STALL_PLAN_20261022.md) 实施；沿用 decoupled，无新分支、worktree 或 agent。
两画布、分辨率、丝绸 shader、玉质双层、完整几何与字库、排版、全部手势、双向无限滚动和两首录音保持。

- 发布模块新增可选 gzip 表示及解码前后两组摘要。包内/COS 存储字节仍由 `bytes/sha256` 描述；
  `contentEncoding/decodedBytes/decodedSha256` 描述原始内容。预览、上传、冲突检测与 HTTP 校验同步支持。
  模型注册表继续校验浏览器恢复的原始 JSON。音频、图片、字体不额外压缩；音频 Range 保持原约定。
- OBJ/GLTF 备用解析器按需要加载，默认完整预计算路径不加载它们。
- 现有属性解码按约 4 ms 工作预算让出主线程；格式、全精度位、索引、几何处理与回退接口保持兼容。
- 既有首屏模块改用 `Range: bytes=0-0` 探测音频，验证状态/类型后取消响应体。
  不支持 GET 时保留 HEAD 回退；未知录音仍读取原生时长。

## 可确认的首载问题

旧公网 `coscroll-24d69d971564297f` 首页主包的**源对象**为 1,327,868 字节。
初始 HEAD 未返回 Content-Encoding，但这不足以判断真实浏览器 GET。补查普通 GET
（`Accept-Encoding: br, gzip`）后，旧 CDN 实际已协商 Brotli。
此前依据 HEAD 推断“客户端主包减少约 74%”不成立，已纠正，没有把它作为优化成果。

| 资源 | 旧普通 GET 的编码/响应体 | 新普通 GET 的编码/响应体 | 结论 |
| --- | ---: | ---: | --- |
| 首页主包 | br，354,664 B | gzip，349,608 B | 实际减少约 1.4% |
| 环境 HDR | 未编码，1,220,313 B | gzip，701,920 B | 无损减少约 42.5% |
| 妙模型预计算 | br，1,606,775 B | gzip，1,609,711 B | 增加约 0.18%，没有宣称此项节省客户端流量 |

主包的真实下载响应均解压并校验至对应发布包的原始摘要；HDR 原始内容未改变，当前表示的
存储与解码摘要已在全量 HTTP 检查中验证。上述三项合计响应体从 3,181,752 降为 2,661,239 字节，
减少约 16.4%；这是三项资源的合计，不是整个首载的百分比。
新版主包解码后的 JS 为 1,274,455 字节，减少 53,413 字节；备用解析器不再属于默认入口。
完整模型属性与索引保持，压缩传输量不等于 GPU/内存占用。

一份旧版心经公网导航中，音频 HEAD 在约 6.05 秒发起，等满 10 秒超时，重试约 17.14 秒结束；
封面约 17.21 秒才出现。新探测保留可用性检查并沿用已支持的媒体 Range 路径；
候选对应的一次单字节探测约 137 ms，不再走这次样本中阻塞首屏的 HEAD 路径。

## 帧率与长帧归因

每行六段 10 秒，共 60 秒，从约 103 秒自然播放经过多个锚字。
普通为 CPU 1×、不限网；压力与首载表相同。P95 是最差分段值；完整原始样本保留。

| 条件 | 旧 FPS | 新 FPS | 旧/新最差分段 P95 | 旧/新最大帧间隔 |
| --- | ---: | ---: | ---: | ---: |
| 普通 | 24.16 | 28.94 | 299.0 / 50.4 ms | 1,050.1 / 1,033.4 ms |
| 压力 | 27.60 | 25.68 | 66.1 / 167.1 ms | 1,033.4 / 333.4 ms |

压力平均帧率单次样本约低 6.9%，前两个分段偏慢；后四段约 29.6 FPS。
该样本没有对应的持续长脚本阻塞，不能据此宣称帧率全面提升或把变化全部归为代码。
独立 CSS 持续动画没有项目脚本、外部资源或 WebGL，60 秒仍仅 28.67 FPS，最大间隔 649.3 ms。

三份真实完整模型的浏览器解码单独对照使用同一 JSON、CPU 4×，暂停渲染以隔离解码；
输出逐属性 SHA 完全一致，包含两层。这里的定时器延迟不是产品 FPS。

| 模型 | 旧/新完整恢复耗时 | 旧/新最大定时器延迟 |
| --- | ---: | ---: |
| 海 | 111.7 / 113.1 ms | 21.9 / 13.6 ms |
| 雨 | 97.9 / 119.7 ms | 16.6 / 12.8 ms |
| 妙 | 95.5 / 94.3 ms | 23.4 / 10.6 ms |

分片缩短连续占用，但有调度成本；这组解码没有复现单个一秒任务。
另一次 60 秒压力诊断用非阻塞 GPU fence 观测完成时间，不能与普通 FPS 样本混为一组。
复现 1,000.3 ms LoAF，renderStart 延后 994.5 ms、scripts 为空；
正文前一帧的 GPU 在提交后 67.6 ms 已完成，距下一次绘制仍约 959.6 ms，
同段定时器/轮询最大间隔约 46 ms。证据指向本测试环境的帧交付/合成调度等待，
不支持“完整一秒都在模型解码或前一帧玉质 shader 中”的解释。

仍能观察到秒级长帧，本轮没有宣称彻底消除卡顿。ego-lite 是桌面 Chromium；
iPhone Chrome/WebKit 真机的帧率、GPU 成本及相同卡顿原因仍未验证。
