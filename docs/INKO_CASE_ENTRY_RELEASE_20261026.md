## 本轮行为

《心经》和《妙法莲华经》分别显示已验收的真实 Inko 原创短序，替换可见的通用开始提示。
每首曲目的文字、输入摘要、生成身份和 PNG 均独立冻结；制作流程与原始来源见
[本地实现验收](INKO_TRACK_OPENINGS_20261025.md)和[曲目制作约定](TRACK_PRODUCTION.md)。
浏览器只读取冻结资源，不调用手写生成服务。图片缺失或校验失败时显示同文文字，开始按钮和手势播放继续可用。

新构建使用 `/CoScroll` basePath，两个站点分别保留小写别名。规范跳转包含末尾斜杠、
曲目选择、重复查询参数、编码字符和子页面；缺失资源跳转后仍返回 404。
默认《心经》按既有规则在客户端移除冗余 `project=heart-sutra`，曲目选择正确；《妙法》保留项目参数。

## 源站切换

71 个源站文件暂存并逐项核验后，只修改两站各自的 CoScroll 路由块，保留各站原有安全响应头。
两份配置保存回滚备份，`nginx -t` 和 reload 均通过，再从源站本机验证两站的 HTTPS 版本健康标记。
当前链接为：

`/www/wwwroot/coscroll-current` → `/www/wwwroot/coscroll-releases/coscroll-7d9ac4d71fe38b81/web`

首次切换前，防护检查发现其他项目并行更新了共享配置，执行了零次配置和入口写入后停止。
只读复核确认 CoScroll 路由、当前版本及邻站页面均未变，随后以最新配置重新合并本次规则，保留其他更新。
实际切换时，除两份 CoScroll 规则和自身发布链接外，其余共享配置、邻站链接及页面摘要与当时基线一致。
验收结束时又检测到共享前缀文件被其他维护更新；两站五条 CoScroll 规则逐条与本次提案相符，
自身发布链接未变，继续保留该后续维护，没有再次写入服务器配置。
