## 改动与原因

- 两曲用到的同源字形先加载 **68,828 字节／309 字形／308 码点**的小包；完整原文件
  **2,447,968 字节／8,106 字形**继续提供，其 SHA-256 保持
  `76e1269db23aa03c8515da4a937bc5a2cb437db3caf65bf3a0fe7b7b26a57af6`。
  首载字体减少约 97.2%，「栴」补字与小包外字的完整回退保留。
- 无墨迹的竖排空格保留原格子、尺寸与位置，跳过绘制；原 U+3000 空白会意外下载完整字库。
- 首页必要脚本合并同一入口的启动依赖，现代浏览器必要 JS 标签由 6 个降到 4 个；
  未将其他实验路由整体搬入首页。字体与页面关键资源完成后再提示大贴图，减少慢网争抢。
- 封面音频用 metadata 预取，用户进入正文后恢复 auto；临近模型同样推迟到进入后。
  正式播放器、音频／seek 回调、配置、全部手势保持兼容，`AudioEngine.preload` 为可选参数，默认 auto。
- 发布复制优先使用文件系统 CoW，独立保留不可变快照；不支持时普通复制。构建限制两个 worker，
  避免本机高交换量导致的资源争抢，不改变网页运行画质或线程数。

小包 SHA-256：`946382846364d5c0797b69227e47d01fe7a394130869af1ecd94bbcb4c245363`。
完整文件未替换、模型未减面、两画布／DPR／shader／双层玉质／排版未降级。
新增经典的生成、回退与验收方法见[接入规范第 10 节](CLASSICS_INTEGRATION_SPEC.md#10-字形分包与首载验收)。

## 帧率与一秒停顿归因

每行由六段 10 秒样本组成；FPS 为 rAF 回调总帧数／总时长，结合 draw 计数观察，
不等同物理屏幕呈现率；P95 为最差一段的 P95。

| 本地候选／曲目 | 60 s FPS | 最差分段 P95 | 最大帧间隔 |
| --- | ---: | ---: | ---: |
| 普通／妙法莲华经 | 29.70 | 34.4 ms | 116.5 ms |
| 普通／心经 | 29.65 | 34.3 ms | 51.0 ms |
| 压力／妙法莲华经 | 30.14 | 34.3 ms | 1,034.1 ms |
| 压力／心经 | 29.24 | 34.3 ms | 1,049.5 ms |

未改代码的旧版也曾测到 60 与 30 FPS；之后 DPR 2 同样约 30 FPS。独立 data URL 页面，
无项目脚本、无 WebGL，只持续移动 CSS 方块，60 秒为 **29.62 FPS**，最大 100.9 ms。
早期“DPR 3 导致半帧率”的猜测未被证实，不能把跨条件结果归功于代码优化。
候选暂停后独立 GPU timer 的背景约 0.56–0.78 ms、正文约 5.05–5.64 ms，未降低视觉配置。

另做 60 秒 GPU fence 压力诊断，复现 **1,049.8 ms** 帧间隔。对应 LoAF 916.8 ms，
renderStart 延后 908.7 ms，绘制回调实际 5.4 ms、blockingDuration=0。
前一帧正文 GPU fence 在提交后 36.4 ms 完成；从该时点到下一绘制回调仍等约 878.1 ms。
期间定时器继续执行，心跳最大间隔 157.8 ms，未记录到 ≥25 ms 的 RAF 回调、
Canvas／WebGL 同步调用或媒体时间读取。此次停顿大部分时长不在前一帧 GPU 或项目脚本执行中，
证据指向本测试环境的帧交付／合成调度，不能据此排除真实 WebKit 的其他瓶颈。

本机 16 GB 内存，调查时交换区约用 9.44 GB，构建中也遇到 ENOSPC；仅清理本轮生成的
废弃交付副本并限制构建并行度。原失败日志、早期候选及工具前提错误记录保留，未用好样本覆盖。
这属于环境背景信息，不能单独证明用户手机问题来自硬件。

**限制：Ego 为 Chromium；iPhone UA 与 DPR 模拟不能验证真实 iPhone Chrome／WebKit。
秒级长帧在压力下仍可复现，本轮未证明手机 FPS 已提高，也未根治全部停顿。**
