# 手机首载、帧调度与播放器节点生命周期验收

状态：本轮代码、双站发布与验证已交付；压力条件下的秒级绘制等待仍存在，不能宣称已消除全部停顿或保证真机 60 FPS。

## 本轮实现

- 首屏资源准备脚本异步执行，模型请求可先于前置样式表完成。贴图在小字体加载后开始预载，取消等待整个页面 `load` 的串行依赖，保留低优先级和失败回退。
- 切曲复用同一 renderer 的法线贴图、环境映射和材质。只重建旋转/模型子树，保留切曲旋转归零；环境强度变化只更新参数。PMREM 的完整 RenderTarget 随组件生命周期释放。
- HDR 与法线贴图均就绪后，在空闲阶段准备最终材质程序，避免只预编译未带齐贴图的早期材质。
- 修复桌面暂停点击丢失：播放器原先在每次进度刷新时重建图标组件，按下的 SVG 节点可能在松开前被卸载。将图标定义移到模块级，保留原图形、尺寸、颜色和音频/seek 接口。
- 切曲故障注入测试改用显式释放条件，避免工具延迟超过原来 700/800 ms 的测试窗口。没有修改产品的切曲时序。

继续使用两画布、完整几何、原材质、分辨率、完整字库和全部滚动/触摸交互。

## 30 FPS 与秒级间隔的证据

- 基线正文的六段 10 s 采样约 29.75–31.12 FPS。另行 GPU timer 诊断中，正文 GPU 平均约 4.72 ms、P95 7.97 ms，背景平均约 0.63 ms；30 FPS 不等于每帧 GPU 工作耗时 33 ms。
- 经用户批准，临时关闭接电低电量模式后，同版本 60 s 正文约 29.52 FPS，独立 CSS 动画约 29.43 FPS，仍未恢复 60 FPS。测试后已恢复 AC 1 / Battery 0。
- 曾记录 1,274.5 ms 长帧，其中 `renderStart` 延后约 1,273.8 ms，脚本列表为空。其他 153 ms、52 ms 的长任务分别保留，不把这些不同情况归为同一原因。
- 后续测试空间被压到后台时，新旧版均约 0.99–1.00 FPS。触摸时间定位仍正确，但旋转速度验收受到限帧影响。经用户许可选择实际可见的测试空间后，短采样恢复约 32 FPS，双曲原生快滑及反向旋转通过。

这些证据支持浏览器/系统调度是本机长间隔的重要来源，尚不能精确归因到单一系统设置，也不能外推为 iPhone 真机结论。
