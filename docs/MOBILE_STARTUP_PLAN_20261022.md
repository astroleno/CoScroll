# 手机首载与转经轮修复（2026-10-22）

用户已确认本轮设计及实现、ego-lite 验证、两个公网入口更新、commit/push。
新增反馈要求恢复手机快速左右拨动，并移除公开的「画面」入口。

## 模块与边界

- 新增首屏资源准备模块：构建时读取目录内两曲配置、原 LRC 和已有完整模型清单，
  校验后写入 HTML。客户端仍经现有配置校验器及 LRC 解析器处理；不匹配、缺失或
  强制刷新时使用原 HTTP 路径。HTML 仅预载 URL 当前选曲的初始模型和公共贴图，
  提前加载完整字体。资源仍使用本次发布的不可变地址，不引入服务端运行接口。
  慢网对照发现同时抢载约 2.5 MB 贴图会推迟字体与脚本，故贴图提示在完整字体就绪后发出，
  优先保证首屏启动；两张原贴图的字节、分辨率与正常材质加载路径不变。
- `prepareProject` 对有离线核实记录时长的录音使用 HTTP HEAD 验证，取消临时 Audio
  的重复加载；无已知时长时仍读取原生 metadata。正式 AudioEngine 报告的实际时长优先。
- 整理 Next 客户端分包，减少 HTTP/1.1 请求排队；只保留实际测试更好的候选。
- `ReadingSession` 保持 12 px/s、预览后提交绝对时间及全部手势接口，捕获活动指针、
  处理最终坐标和连续反向拨动。`useScrollVelocity` 提供内部即时速度引用，正文模型
  在 Three 帧循环读取；真实 visibilitychange 与手势分开，松手后角速度平滑回到默认。
  歌词与音频仍在手势结束后回到同一个绝对时间，不引入独立漂移的歌词惯性时间轴。
  用户补充实际问题出现在 iPhone Chrome：正文使用非 passive 原生 TouchEvents，
  鼠标/笔继续使用 PointerEvents，两条路径互斥；处理触摸结束最终坐标，不依赖触摸指针捕获。
- 移除 `ClassicControls` 的公开画面按钮和面板，保留按曲目的现有配色数据和经典切换。

## 验收

两画布、画布分辨率、丝绸公式、完整模型、玉字内外层及透射、完整字库与排版保留。
用 ego-lite 对比相同手机模拟环境的网络瀑布、首载、正常/压力各 60 秒帧间隔、GPU
与 React 更新；核对多角度固定画面，连续快速双向拨动、松手缓动、慢拖、跨轮、滚轮、
键盘、进度条、暂停续播与切曲。失败样本保留，不把电脑模拟称作手机真机。
完成本地后使用正式 CDN/COS 包，完整校验两域名的资源、音频 Range 与版本，再提交推送。
