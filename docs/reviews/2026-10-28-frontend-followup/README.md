## 404 响应头判断

本轮重新读取两站正常入口、健康标记及通用 404 响应，并查看错误页实际内容。正常 CoScroll 页面及健康标记均有 `X-Frame-Options: SAMEORIGIN`；错误页实际为 146 字节的 Nginx 静态提示，只有“404 Not Found”与“nginx”，没有表单、按钮、用户数据或敏感操作。

| 抽查对象 | aitoshuu.me | tongye.me |
| --- | --- | --- |
| 正常 CoScroll 入口 | 200，有 SAMEORIGIN | 200，有 SAMEORIGIN |
| `release-health.json` | 200，有 SAMEORIGIN，版本匹配 | 200，有 SAMEORIGIN，版本匹配 |
| 不存在的 CoScroll 路径 | 真实 404，有 SAMEORIGIN | 真实 404，缺少 X-Frame-Options |
| 404 内容 | 146 字节纯静态错误提示 | 相同字节与摘要 |

`X-Frame-Options` 与 CSP `frame-ancestors` 用于限制页面被嵌入，从而防御基于框架的点击劫持；机制参见 [OWASP Clickjacking Defense](https://cheatsheetseries.owasp.org/cheatsheets/Clickjacking_Defense_Cheat_Sheet.html)。基于本轮实际页面内容，我将该缺失判断为**低优先级的配置补齐项**：可嵌入的只有无操作内容的错误提示，正常产品页面已有相应保护，不影响播放、模型、手写开场或阅读。

用户授权“影响大就直接改”，本项经调查没有达到立即修改共享网关的必要性。因此本轮记录现场事实，建议以后统一维护错误页时补齐，没有修改腾讯或阿里共享配置。此判断针对本次抽查的静态 404，不代表全站安全审计；若错误页以后加入账号数据或操作入口，应重新评估。
