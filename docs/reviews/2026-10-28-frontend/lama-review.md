# CoScroll 前端独立审阅：lama 视角

日期：2026-10-28。审阅范围：正式入口的 UI/UX、概念一致性与心流沉浸感；只形成评审文档，没有修改产品代码。

## 判断与应保留的长处

当前产品概念是成立的：声音提供时间，竖排歌词组成可往返的卷轴，玉字成为视觉锚点，丝绸提供连续的空间。它适合保持为一件可以操作的听读作品；不需要增加首页卡片、底部导航或一组设置来证明功能完整。

本轮桌面与 Android UA 仿真中，手写短序、正文、选曲面板使用一致的明暗与曲目色系。开场没有重复曲名和水印，中央只留与曲目相关的三行短序；正文的控制主要集中在上下边缘，没有用解释性文案占据阅读中心。E01、E09、E10 的这些取舍应保留。

控制链路也有值得保留的基础：开场由用户操作进入，曲目面板是短暂覆盖当前作品的选择任务，切换后从曲首开始且保留暂停状态；Esc 关闭后焦点回到曲名入口，横向触摸可在暂停时改变进度。这些行为使用户能介入和退出，而不会为了换曲离开作品的空间。证据见 E02、E03a、E11、E11a。

需要优先补齐的是矮屏完整性、核心控制的触摸容错，以及用户主动选择减少动态效果时的安静版本。另有一处曲目类型信息未进入界面，影响“随声观经”的内容预期。这四项足以构成下一轮范围，无须同时改造整体视觉语言。

## 发现

### L-01 · P1 / 高信心：横屏的内容仍按高场景排布，正文出现上下硬截断

**场景与观察。** 在 Android UA 的 844×390 横屏中，已进入并暂停的《妙法莲华经》位于约 75.83 秒。E12 可见多列歌词在上、下边界被直接截去，玉字下部也触及正文的截断线；这不是左右边缘淡出，也不是已确认的玉字遮挡后景歌词。DOM 中正文只有 262px 高，播放器区域仍为 128px，占整个视口约三分之一。桌面矮窗 E02 也提示相同的高度风险，但本条手机结论以 E12 为依据。

**源码事实。** [ReadingSession.tsx:849](../../../src/components/ReadingSession.tsx#L849-L895) 将场景放在 `overflow-hidden` 的剩余空间中；[ReadingSession.tsx:900](../../../src/components/ReadingSession.tsx#L900-L928) 的 footer 使用固定上下留白。场景仅按 UA 与 `innerHeight < 667` 选择一组参数，[UnifiedLyricsAndModel.tsx:78](../../../src/components/layouts/UnifiedLyricsAndModel.tsx#L78-L115) 没有依据正文实际高度安排列长；[同文件:137](../../../src/components/layouts/UnifiedLyricsAndModel.tsx#L137-L141) 的正交相机使用固定 zoom。长句按原长度生成竖排，[layeredLyrics.ts:154](../../../src/components/layouts/layeredLyrics.ts#L154-L160) 仍锚定到固定上下轨道。

**影响与推断。** 用户横过手机后仍能调进度，却不能完整看到作品中的字句，注意力会从听读转向寻找缺失部分。`overflow=false` 只能说明页面没有横向溢出，不能证明 Canvas 内的内容没有裁切。

**建议。** 先在矮屏收回播放器区域的空白，为作品保留高度，并以实际正文尺寸建立矮屏的完整性验收。若仍无法容纳，应明确确认矮屏的分句/列布局规则，再实现适配。保持竖排、前后层次、完整模型、两画布和音频同步；不删字、不用裁切掩盖，也不把静默缩小字体或改相机参数当成无风险修饰。涉及字号比例或相机的调整需按原视觉规范确认受影响设计。

**验收标准。** 在 844×390 及矮桌面窗口复现 E12/E02 的时刻，当前句与代表性最长句的首末字不被上下视口截去，玉字完整性可确认；保留允许的前后遮挡，控制仍可点击、拖动和键盘操作。390×844 竖屏及原桌面基线不发生比例回退；两首歌都取样验证。

### L-02 · P2 / 高信心：安静的控制外观没有配上足够宽容的触摸区域

**场景与观察。** E10/E11 的手机仿真中，播放按钮基础尺寸为 32×32px，悬停缩放时约为 33.6×33.6px；播放进度 input 为 190×6px。曲名入口高 41px。细线和小图标在视觉上克制，但实际可操作区域也跟着缩小；本轮没有测量误触率，不能声称用户已经频繁点不中。

**源码事实。** [EnhancedAudioPlayer.tsx:25](../../../src/components/audio/EnhancedAudioPlayer.tsx#L25-L34) 的图标为 32px，[同文件:166](../../../src/components/audio/EnhancedAudioPlayer.tsx#L166-L175) 的按钮没有独立最小热区；[同文件:200](../../../src/components/audio/EnhancedAudioPlayer.tsx#L200-L227) 直接把原生 range 高度设为 6px，thumb 为 16px，并默认透明，[同文件:270](../../../src/components/audio/EnhancedAudioPlayer.tsx#L270-L305)。曲名入口由字体与内边距决定高度，[ClassicControls.tsx:58](../../../src/components/ClassicControls.tsx#L58-L65)。

**影响与推断。** 暂停和细调是作品中最需要用户准确接管的动作。触摸容错不足会让用户为了操控而提高注意力，削弱沉浸；滑块没有常显 thumb 也使手机用户更依赖已知的播放器经验。这是触摸体验建议，不是依据 44px 机械宣称 Web 标准不合规。

**建议。** 保留图标和细线的可见尺寸，在现有播放器留白中给播放/暂停、曲名入口及滑块建立至少 44px 的有效触摸区域。range 的交互高度与可见轨道高度分开，进度语义仍由原生 input 承担；无需添加大按钮、厚背景或新的操作层。

**验收标准。** 在 390px 宽粗指针环境，按钮中心及四周留白均命中同一动作；滑块上下偏离可见线仍能开始拖动，结束或取消时只提交正确目标，不误触正文拖动。保留聚焦可见性、Home/End、方向键与暂停状态下的定位；扩大热区不挤占 L-01 所需的正文空间。

### L-03 · P2 / 高信心：系统已请求减少动态效果，正式场景仍持续自转与流动

**场景与观察。** E08/E08b 中 `prefers-reduced-motion: reduce` 为真，录音保持暂停在约 75.83 秒；两次图像之间玉字姿态仍有变化。这里不是断言“暂停音频必须冻结作品”，而是系统明确的运动偏好没有作用于装饰性运动。

**源码事实。** 正式入口导入的是 [ClassicExperience.tsx:11](../../../src/components/ClassicExperience.tsx#L9-L11) 的 `SilkR3F`，并持续传入背景动画参数，[同文件:64](../../../src/components/ClassicExperience.tsx#L64-L66)。[SilkR3F.tsx:108](../../../src/components/backgrounds/SilkR3F.tsx#L108-L115) 持续更新时间，[同文件:162](../../../src/components/backgrounds/SilkR3F.tsx#L160-L164) 持续渲染；[UnifiedLyricsAndModel.tsx:178](../../../src/components/layouts/UnifiedLyricsAndModel.tsx#L178-L187) 始终开启玉字旋转，没有连接减少动态效果偏好。另一份 `SilkBackground.tsx` 虽有相关检测，并未进入本入口，不能据此认定已支持。

**影响与推断。** 对偏好安静或对运动敏感的访问者，声音、歌词的必要进度与持续装饰运动没有区分，难以由用户决定注意力负担。本轮没有运动不适的用户测试，不能量化影响人群，也不据此推断 FPS 或耗电。

**建议。** 先让系统偏好进入正式渲染链路：减少模式中固定丝绸的时间与玉字的自主旋转，保留相同材质、文字、完整几何和两画布；直接拖动、定位和音频的因果关系继续明确。播放中的歌词应如何减少大范围运动，需要在保持同步的前提下确认，不建议借此直接替换为另一种播放器或新增一页设置。

**验收标准。** 在相同暂停时间及无输入状态，两次画面中的背景和模型姿态保持静止；减少模式进入、暂停、定位、换曲均正常，恢复普通偏好后原有效果恢复。正常模式视觉基线不变，并分别验证系统偏好在首次进入与运行中改变时的行为。

### L-04 · P2 / 高信心：妙法曲目的摘编歌曲属性停留在配置，没有进入选曲信息

**场景与观察。** E03、E11 的选曲面板中，《心经》显示“王菲 · 歌曲版”；《妙法莲华经》显示“赞诗 · 神农尝百草·卷一”。后者说明了演唱者与专辑，却没有说明它是摘编歌曲。面板总标题仍为“经典”，用户可能将作品名理解成全本经文的播放范围；这是内容预期风险，不声称现有文字明确谎称全本。

**源码事实。** [lotus-sutra-zanshi.json:6](../../../public/projects/lotus-sutra-zanshi.json#L3-L8) 已准确保存“摘编自《妙法莲华经》，非全本诵读”，但 [catalog.ts:3](../../../src/config/catalog.ts#L1-L4) 的选曲信息只给出专辑；[ClassicControls.tsx:48](../../../src/components/ClassicControls.tsx#L46-L50) 只渲染 artist 与 recording，未呈现该范围。

**影响与推断。** “观经”的承诺既包含氛围，也包含正在听哪一种内容。只有开始播放后才靠时长与歌词自行判断录音范围，会削弱概念的准确性；新增更多曲目后，这种录音版本差异也更难比较。

**建议。** 保留曲名、演唱者和现有入口，在面板的曲目副信息中统一呈现录音类型，例如“歌曲版”“摘编歌曲”，专辑作为次级来源保留。把内容范围说明放在做选择的地方即可，不需要把“非全本”或来源说明放回中央手写开场，也不需要重写序言。

**验收标准。** 用户打开选曲面板即可读到并通过辅助名称获知《妙法》为摘编歌曲；两首采用一致的“作品名／录音版本／来源”信息层级。窄屏文字不被截断，曲名与原录音来源保持准确，换曲行为不变。

## 不应误判为问题的内容与后续边界

纯短序开场、公开界面不展示水印与中央重复曲名，均是已确认的方向，本轮不建议加回“点击一下”的提醒。玉字与歌词互相遮挡、边缘渐隐、双向无限滚动是作品的核心构成；L-01 仅针对上下视口硬裁切。两首各用自己的色系不属于“多强调色失控”，没有必要强制统一成单一原生应用主题。

E05 曾记录“模型加载中：生”，但稳定状态 E10 已显示本字、状态为空；不能将正常加载瞬间写成仍有字形占位。当前配置的“圆”使用现有库中的本字模型，历史报告里的兼容占位不作为新发现。右侧粉红色悬浮图标来自浏览器插件，也不属于产品。

以上建议保持为 review 结论；本文件不授权改代码、提交、推送或发布。若进入迭代，先确定 L-01 涉及的矮屏呈现规则，再将扩大热区、减少动态效果与录音类型信息组成有边界的改动；无需借此新增框架、导航体系或通用组件平台。
