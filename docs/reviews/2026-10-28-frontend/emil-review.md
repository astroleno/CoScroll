## 概念与已经成立的部分

CoScroll 的核心是由声音展开的一卷文字：竖排提供阅读路径，玉字把锚点变成可感知的物体，丝绸维持连续空间。当前视觉已经能够支撑这一概念。E01 的手写序言与 E02 的立体锚字形成从人的笔迹进入经卷的层次；E09/E10 的青竹色延续同一材质语言，不需要为第二首再建立另一套界面。

最值得保留的是操作层的克制。选曲缩在一角，播放器留在底部；没有把百字模型库做成干扰正文的展示目录。开场遵守用户的进入手势，而非自行发声。[开场按钮](../../../src/components/AutoPlayGuard.tsx#L37)有语义名称与键盘焦点，[同文后备](../../../src/components/OpeningPrompt.tsx#L34)使图片失败不至于让内容消失。

界面也有一些容易被忽略的正确性：[经典面板](../../../src/components/ClassicControls.tsx#L20)使用原生 dialog 并归还焦点；E02 的 range 虽然去掉默认 outline，滑块仍有可见焦点反馈，不能只凭 `outline: none` 报错；[手势](../../../src/components/ReadingSession.tsx#L473)限制单个指针并使用 capture，[新定位](../../../src/components/ReadingSession.tsx#L361)会清除过时预览。这些处理让操作可以被用户随时接管，比再加一种进场动画更有价值。

## 主要发现

这里的 P2 表示值得在下一轮解决的体验缺口，不表示当前全部用户的主路径已经阻断；P3 表示需先验证的设计假设。本轮没有证据支持 P0/P1 级的普遍可用性故障。

按所选 skill 的要求，用 Before/After 表达改进方向。以下均为建议，不是已经批准或完成的实现。

| Before | After | Why |
| --- | --- | --- |
| **E-05 · P2**：844×390 横屏中，固定 footer 占 128 px，剩余主区 262 px；稳定玉字下部被截，多列经文越过上下边界。 | 定义短高视口的整体取景与控件留白规则，保留玉字/经文的相对比例和材质。 | 横屏应仍可观字与观句；不能把“没有横向 overflow”当作内容完整。 |
| **E-01 · P2**：播放器按钮约 32×32，range 元素高 6 px；视觉上的纤细也落在实际控件边界上。 | 保留图标和细线的外观，为按钮和进度条提供更宽容的透明命中区域。 | 避免在本应放松观看时反复瞄准；先改善操作成功率，不增加界面重量。 |
| **E-02 · P2**：正式丝绸与玉字链路未消费系统减少动态效果偏好，暂停声音也不等于停止装饰运动。 | 在系统减少动态效果下抑制自发背景流动与基础自转，保留明确操作后的必要反馈。 | 沉浸应允许用户控制刺激量；保持材质与布局，不等于必须一直运动。 |
| **E-03 · P2**：正文歌词只作为 WebGL 纹理存在，没有可读的语义文本途径。 | 从同一份歌词提供按需可访问的文本路径；保持默认场景简洁，不逐句自动播报。 | “观经”不应只能通过画布像素完成；文本替代也能承接被遮挡时的确认需求。 |
| **E-04 · P2**：《心经》显示“歌曲版”，《妙法》只显示专辑名；配置中的摘编属性未传达到选曲信息。 | 在选曲详情明确“摘编歌曲”与录音来源；保持正文和开场现有精简。 | 让作品形式与读者预期一致，避免把歌曲的结束误解为全本经文的结束。 |

### E-05：横屏短高视口损失了完整的观字空间

**证据与信心：已观察 + 源码确认，高。** E12 是明确 Android UA 仿真中的稳定模型，不是模型下载中的瞬间；在 844×390 视口里，玉字“生”的上缘仍可见，下部被主区底界截断，多列竖排文字则有上下截界。记录中 main 为 262 px，footer 为 128 px，后者占总高度约 33%。[footer 的 `py-8`](../../../src/components/ReadingSession.tsx#L899)与播放器内边距形成固定留白；[短屏规则](../../../src/components/layouts/UnifiedLyricsAndModel.tsx#L81)只小幅调整字号和 y 偏移，[玉字 scale 与相机](../../../src/components/layouts/UnifiedLyricsAndModel.tsx#L109)没有相应的短高取景规则。没有横向页面溢出、模型状态 ready，都不能排除这种可见范围损失。

**沉浸影响：** 屏幕从可观看的玉字变成局部笔画，观看需要额外改变视口或姿态。这里不把前后经文有意遮挡等同于错误，也不推断这一个时点代表所有曲目、全部姿态。

**受约束建议：** 先设计一个明确的短高视口策略：在保证触控命中高度的前提下压缩 footer 空白，再联合评估整体相机取景与正文区域。保持玉字和经文的相对比例，不能只缩小玉字、减面、删句或强制竖屏来声称适配。

**验收：** 844×390 和更短高的目标视口中，稳定锚字至少三个姿态可完整观看，当前句有可读路径，标题与正文不冲突；竖横切换不重置播放位置、音频或手势。与当前竖屏/桌面固定时点对照，原有材质、比例、遮挡关系和清晰度保持。

### E-01：细控件需要更宽容的命中边界

**证据与信心：已观察 + 源码确认，高。** E02 的 DOM 记录中播放按钮为 32×32 CSS px，进度条为 472×6；[图标和按钮](../../../src/components/audio/EnhancedAudioPlayer.tsx#L166)没有额外 padding，[range](../../../src/components/audio/EnhancedAudioPlayer.tsx#L200)的 `h-1.5` 对应 6 px。E10/E11 的 Android UA 竖屏仿真中进度条宽度为 190 px，同样高 6 px；播放按钮基础为 32×32，悬停缩放时可到 33.6×33.6。这里测得的是元素边界，没有据此声称已发生触摸失败，浏览器对原生 thumb 的额外命中容差也未测量。

**沉浸影响：** 用户从中央经卷转到底部调整时，需要把注意力切换到精细定位。问题是操作容错，不是进度线应当画得更粗。本轮没有统计误触率，也不据此下无障碍标准符合性结论。

**受约束建议：** 先把按钮与 slider 的透明可操作高度设计到约 44 px，保留 32 px 图标、细轨道、原位置和现有 range 语义。需要同步核对底部剩余空间，避免单纯扩大 footer 压缩经文；hover 装饰仅用于真正支持悬停的指针。

**验收：** 手机与桌面分别点击图标/细轨上下的目标区域仍能操作；滑动后松手与取消只提交预期位置；键盘焦点仍清楚；固定时点对照中正文比例、底部留白和轨道视觉不变。真机触摸仍需另测。

### E-02：减少动态效果尚未到达正式画面

**证据与信心：已观察 + 源码确认，高；对具体人群的感受影响为设计判断。** E08/E08b 的记录中 `reduce=true`、媒体均暂停在 75.833333 秒，两张截图仍能看出玉字姿态变化；这不是流畅性或 FPS 测试。正式页导入的是 [SilkR3F](../../../src/components/ClassicExperience.tsx#L11)，其 [逐帧时钟](../../../src/components/backgrounds/SilkR3F.tsx#L108)持续推进；[正文配置](../../../src/components/layouts/UnifiedLyricsAndModel.tsx#L178)始终开启玉字旋转并提供非零基础速度，[旋转器](../../../src/components/jade/JadeModelLoader.tsx#L257)在启用后不检查播放状态或系统偏好。旧 `SilkBackground.tsx` 的减少动态效果代码不在这条正式链路，不能当作已经支持。

**沉浸影响：** 对希望静观、对持续运动敏感的用户，声音暂停以后仍无彻底安定下来的路径。这里不把持续自转本身视为错误，它符合现有物体语言；缺口是缺少与用户偏好相配的静止方式。

**受约束建议：** 先响应系统偏好，冻结装饰性丝绸时钟和基础自转，保留丝绸画面、玉质、原有两画布与手动定位能力。歌词怎样在减少动态效果下随音乐更新，应单独定义清楚，不能简单把视觉时间停住而让声音继续走。无需为此加入弹簧库或新增默认可见设置面板。

**验收：** 偏好在进入前或运行中改变均能生效；静止/轻量更新策略没有音画错位；显式拖动、播放暂停、切曲和自然循环仍可理解；普通偏好下画面与当前版本保持一致。

### E-03：正文缺少画布之外的阅读路径

**证据与信心：源码确认 + 浏览器结构记录，高；未做读屏软件实测。** E02/E10 的页面结构包含两个 canvas、播放控件和选曲标题，没有正文句子；E10 的 `body.innerText` 也只有时间和标题。[正文入口](../../../src/components/ReadingSession.tsx#L849)只把歌词交给场景；[分层场景](../../../src/components/layouts/LayeredLyricsScene.tsx#L130)创建 billboard，[billboard 最终输出](../../../src/components/layouts/LyricBillboard.tsx#L138)为带纹理的 mesh，没有配套 DOM 经文。开场短序已经有文本语义，进入正文后反而丢失这种可读性。

**沉浸影响：** 不依赖视觉的读者无法读取核心内容；视觉读者遇到前后遮挡、截出视口的列时，也缺少一种主动核对文本的方式。前后遮挡是已确认的艺术设计，本发现不要求取消遮挡或改变字号比例。

**受约束建议：** 用现有已校验的 `lyrics` 提供语义阅读途径，可以在既有面板中按需打开，或提供适合辅助技术的文本入口。不要再维护一份经文、不要用全屏新列表替换默认场景，也不要让 live region 随音乐逐句抢读，覆盖原有录音。

**验收：** 正文在浏览器无障碍树中可找到并按内容顺序读取；用户可主动进入、退出该路径且焦点有去处；换曲后只出现本曲歌词；没有重复播报；画布布局与手势仍保持。之后用真实读屏软件复核。

### E-04：曲目形式需要在选择处说清楚

**证据与信心：已观察 + 源码确认，高。** E03 显示“心经 / 王菲 · 歌曲版”和“妙法莲华经 / 赞诗 · 神农尝百草·卷一”。[目录](../../../src/config/catalog.ts#L1)只给后者专辑信息，[面板](../../../src/components/ClassicControls.tsx#L46)只呈现 `artist` 与 `recording`；[曲目配置](../../../public/projects/lotus-sutra-zanshi.json#L6)已有“摘编自《妙法莲华经》，非全本诵读”，但未呈现。这里不主张实际歌词错误或漏接全本。

**沉浸影响：** 选曲处是用户建立作品预期的时刻。标题为整部经典，副标题没有说明摘编歌曲，可能让不熟悉录音的读者把四分钟体验理解成整本内容。该误解尚未通过用户实验验证，但信息差可以直接确认。

**受约束建议：** 在面板沿用现有副标题层级，简短说明“摘编歌曲”，同时保留赞诗与专辑来源。无需把来源、AI 标识、重复曲名放回中央手写开场。

**验收：** 两曲的录音形式同样明确；窄屏副标题完整可读；从两个曲目的直接入口与切曲入口都能在同一面板查到，正文保持原样。

## 需先验证的设计判断

**首次进入的可发现性（P3，中等信心）。** E01/E09 的短序现在有呼吸感，且“点击开始”已按用户决定从视觉中移除。第一次来的访客是否理解整屏可点，静态截图不能回答；本轮成功 Enter/触摸也不等于首次使用者测试通过。若后续有人停留却不知道如何开始，先观察其首次操作，再试验不影响序言的聚焦/指针反馈，不默认恢复旧提醒语。

**暂停后的静观（P3，中等信心）。** 玉字继续转动可以是作品的生命感，也可能让某些人觉得“暂停了却还没停”。系统减少动态效果可先解决有明确偏好的情况；是否让普通暂停冻结所有装饰，需单独比较体验，不凭通用播放器惯例改动。

## 建议迭代顺序

先处理短高视口的取景与操作容错，顺带说清曲目形式；再补系统减少动态效果和可访问正文路径。短屏取景与正文替代路径需要先明确行为设计，不能以本审阅直接视为改版批准。每轮继续保留现有材质与空间关系，不需要先做全面视觉改版、增加日常可见控件或扩大模型系统。

这些是本次独立审阅结论，不是发布验收、用户研究结论或已获批准的修复清单。
