## 腾讯源站与公网 HTTP

腾讯上海 `122.51.59.89` 暂存全部 71 个源站文件，核对文件集合、长度和 SHA-256 后，通过 `nginx -t`，原子切换：

`/www/wwwroot/coscroll-current` → `/www/wwwroot/coscroll-releases/coscroll-2a582f7e773a84d4/web`

两站回环 HTTPS 和公网健康标记均为本次 release ID 与源码摘要；成功文件的响应带 `X-Project-Origin: tencent-shanghai`。三个腾讯相关配置文件在切换前、切换后及最终审计时摘要一致，没有修改共享 Nginx、DNS、证书或 CDN 策略，没有重载 Nginx。保留原有 `_` server name 冲突警告。

| 检查 | 实际口径与结果 |
| --- | --- |
| 完整共享 CDN 内容 | 309 个存储字节摘要及长度、210 个 gzip 表示的解码后摘要、MIME、缓存和 CORS 全部通过 |
| 下载限速 | 四路，每路最高 150 KiB/s；与浏览器大文件下载错开，未调整现有 10 Mbps 带宽配置 |
| 每站源站文件 | 各 71 个真实 GET，逐项比对摘要、长度、MIME、缓存及成功响应的安全头、腾讯标记 |
| 每站 CDN 元数据 | 各 309 个 HEAD，核对摘要元数据、发布标记、长度、MIME、编码、缓存及 CORS；未将 HEAD 记为重复完整内容下载 |
| 音频 | 完整 CDN 检查含 4 个真实 1024 字节 Range；两站另各核对 4 个 Range 的 206、Content-Range、CORS 和字节摘要 |
| 每站入口 | 各 8 类 308，覆盖正式、小写、混写、末尾斜杠、重复查询参数及编码子路径，均留在本站 |
| 每站缺失文件 | 各 2 类真实 404；错误页响应头差异见下段 |
| 邻站 | 两站首页、小写 LuBirth 跳转及正式 LuBirth 页面共 6 个状态、跳转和页面摘要与切换前一致；tongye 首页现有 302 到 `/experience/` 也按实际基线保留 |

两站全部成功源站文件的 HSTS、nosniff、SAMEORIGIN、Referrer-Policy 和腾讯标记通过。网关通用 404 均有 HSTS、nosniff、Referrer-Policy，均无腾讯来源标记；aitoshuu 的错误页有 SAMEORIGIN，tongye 的两类错误页缺少 `X-Frame-Options`。这是本轮实际观察到的共享错误响应差异；本轮只切换应用静态目录且腾讯配置摘要未变，没有修改共享网关来掩盖检查差异，也没有宣称该项已修复。

检查器最初把成功源站文件的全部响应头要求套用于通用错误页，完整审计因此报错。随后保留成功文件的严格校验，将通用 404 的各项头值单独记录并明确上述缺失，再完整重跑两站内容、入口和邻站检查通过。原始结果随正式版本保存在服务器发布目录的非 `web` 区域。
