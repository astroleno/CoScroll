# iPhone 加载与长帧排查（2026-10-22，第二轮）

目标：保留当前画面、两画布、完整可用字形、模型、排版及全部手势，查清启动、约 30 FPS
和偶发一秒长帧的可观测原因，优化后 ego-lite 复测，发布两个公网入口并 commit/push。
沿用 `decoupled` 和既有启动、缓存及部署架构，不创建 agent、分支或 worktree。

## 已有证据

- 当前公开版本 `coscroll-995562e8da979533` 的一次 iPhone UA / DPR 3 导航中，主字体约
  7.8 秒就绪、初始模型请求约 7.5 秒完成，但一份 104,834 字节的必要 JS 请求直到 24.1 秒
  才结束，封面约 24.3 秒、原生音频有数据约 33.7 秒。须分离请求排队/传输和应用工作，
  不把所有慢首载归因于字体解析或 GPU。
- 暂停、仅背景和仅正文也出现长帧；约 984–998 ms 的 LoAF 中，renderStart 发生在
  结束前约 1–2 ms，归因脚本为空、blockingDuration=0。CPU 采样存在约 905 ms 的
  无采样间隔，之前为 idle、之后为 program。证据不支持“一秒都在执行歌词 JS”。
- 同一个未改代码的版本在 DPR 2 的暂停对照中达到约 60 FPS，DPR 3 的对照约 30 FPS。
  后续 DPR 2 也出现约 30 FPS，且无项目脚本、无 WebGL 的独立持续 CSS 动画为 29.62 FPS。
  因而早期 DPR 猜测未证实；不能拿跨条件结果宣传代码将 30 FPS 优化成 60 FPS。
- 原字库 2,447,968 字节、8,106 字形；只读原型将两曲用字、标题与 ASCII 等同源字形
  原型为 68,956 字节，正式保留全部全局度量后的包为 68,828 字节、309 字形／308 码点。
  原完整文件没有修改；已按下述确认接入并完成逐字轮廓、hinting、度量与浏览器像素检查。

实施期间发现，竖排空白占位的 U+3000 会激活完整字库；现保留格子尺寸并跳过空格绘制。
小包变快后，过早请求 HDR／法线贴图又会挤占必要 JS；贴图预载改为同时等待字体与页面 load。
封面音频用 metadata 预取，用户进入后恢复 auto；临近模型也推迟到进入正文，原音频与手势接口兼容。

最终候选正常／压力每曲各 60 秒。压力样本仍出现约一秒的动画帧间隔，但对应脚本、Canvas／
WebGL 同步调用和媒体时间读取均无同长阻塞，10 ms 定时器也继续运行。独立 GPU fence 的
60 秒压力对照复现 1,049.8 ms 帧间隔：LoAF 916.8 ms 中，renderStart 延后 908.7 ms，
回调实际执行 5.4 ms；前一帧正文 GPU 在间隔开始后约 30.6 ms 已完成，其后仍等待约 878.1 ms
才收到下次绘制回调，心跳最大间隔 157.8 ms。该样本不支持项目脚本或前一帧玉质 shader
持续执行一秒的解释，证据指向本测试环境的帧交付／合成调度；不冒充真实 iPhone 的归因结论。

## 已确认范围内继续

调整现有首页脚本分包以减少关键请求的尾部延迟；检查既有文字纹理、材质准备与渲染循环
是否重复分配、同步等待。保持现有接口和视觉公式。所有归因以同条件的请求/CPU/长帧/
GPU/持续重绘对照为准；临时禁用渲染或 CSS 仅用于诊断，不作为正式优化。

## 已确认的新字体加载流程

扩展现有字体打包工具，生成两曲当前字形的小包和明确的 Unicode 范围数据；HTML 先请求
小包，同一字体族用不相交的 unicode-range 保留原完整字库为其余字符服务。`栴` 仍用现有
补字。完整原字库继续随发布提供，不降低字形精度；未来经典出现新字符仍走完整文件。
既有配置、音频、字体族、文字纹理配方和手势接口不变。

用户本轮已确认这项新增资源加载流程。对每个小包字符核对源字形轮廓、度量及布局
表，检查主/补字/未知字符的加载与回退，比较两曲多角度画面；源文件保持可校验的原始字节。

## 验收与交付

- 记录 HTML 首字节、关键脚本/字体/初始模型、背景首绘、封面、原生音频分别的时点。
- 同条件 iPhone UA、DPR 3 与 DPR 2 对照；正常/压力各至少 60 秒，单列一秒长帧和 CPU、
  GPU 证据，保留失败样本。ego-lite 是 Chromium，不宣称测到了用户物理 iPhone。
- 两曲、双向无限多轮快拨/慢拖/抬手/取消、鼠标/键盘/进度条、自然循环、暂停和切换；
  保留全分辨率画面并做固定帧像素对照。
- 构建、必要运行时与部署检查通过，完整验证 CDN/COS 和两个公网入口，再提交推送；
  仍存在的问题明确记录，不以单个好样本或平均 FPS 掩盖。
