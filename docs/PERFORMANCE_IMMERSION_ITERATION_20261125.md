# 性能、画面与沉浸体验复核

2026-11-25。Astra 审阅并确定验收，Sol 实施，再由 Astra 检验。对照源码为 `4b0132f`，两站公网健康标记均为 `coscroll-2a582f7e773a84d4`。公网资料参见[上一轮验收](FRONTEND_IMMERSION_RELEASE_20261028.md)。

## 评审发现

1. **绘制恢复时，歌词位置可能落后录音。** `ReadingSession` 已逐帧读取原生音频时间，`lyricMotion` 却继续用 `speedProfile` 的稀疏采样预测。Astra 用当前函数模拟绘制中断 1 秒而录音持续，30 / 60 Hz 分别落后约 819 / 813 ms。媒体样本固定两秒时，歌词又可提前约 168 / 88 ms。以上为确定性函数复现。历史手机大小仿真确有接近一秒的绘制等待，调度原因与真机情况参见[过往记录](MOBILE_FRAME_STARTUP_RELEASE_20261023.md)。
2. **减少动态效果模式下，丝绸纹理静止，背景 Canvas 仍持续重绘。** `SilkR3F` 冻结 shader 时间，Canvas 却仍使用连续绘制。静止时重复绘制相同像素可省去，配色、尺寸变化和恢复动效时仍须正确出图。

歌词窗口预热可能重复调用整场材质准备，现有证据不足以量化可见影响。列为后续观察。

## 实测结果

专属手写短序给两首曲目留下了独立开场，丝绸、玉字与前后竖排把注意力留在声画内容。正常播放时，歌词跟住录音比增加视觉效果更能维持阅读。两项迭代分别处理时间偏差和静止背景的重复工作。

本地使用同一 Chromium、390×844 手机仿真、DPR 2，前景上限仍为 1.8。对照本地生产导出 `coscroll-d59d97e56ea0886d`，候选为 `coscroll-afd99fd78b651f34`。在各曲同一行内测试性停止前景绘制约 1 秒，原生音频保持播放，从恢复时实际绘制的歌词列坐标反推布局时间。背景计数窗口各为 5 秒。

| 项目 | 心经，120 秒附近 | 妙法，64 秒附近 |
| --- | --- | --- |
| 恢复首帧歌词与录音的偏差 | 约 958 ms → 本次测得 0 ms | 约 999 ms → 本次测得 0 ms |
| 减动开场背景绘制 | 123 → 0 次 | 102 → 0 次 |
| 减动暂停背景绘制 | 134 → 0 次 | 35 → 0 次 |

候选恢复后连续四帧均与当时样本对齐。以同一代码独立复现 30 / 60 Hz 确定性对照，候选在 1 秒绘制停顿后使用新样本，原生媒体时间冻结两秒时仍停在原句。动效恢复后两曲背景均继续绘制，前景仍按原布局处理输入和播放。常规播放仅各取一段约 3 秒的短窗，心经 30.1 → 25.5 FPS，妙法 18.3 → 20.6 FPS。共享环境中波动较大，这些数字不足以判断帧率变化趋势。

两曲固定画面均对比同尺寸背景与三个相同玉字角度。丝绸背景逐像素一致，前景的姿态、材质参数、顶点数和画布尺寸一致。最差一张正文画面 904,176 个像素中相异 15 个，最大通道差为 14/255，P99 为 0。最初沿用最大通道差 2/255 的门槛时超出，复核差异落在零星经文边缘，同一曲目在不同玉字角度下的差异幅度一致。Astra 复核没有发现可辨识的画质下降。

## 本地候选交互补验

- 妙法在约 64 秒暂停后转到 844×390 横屏。背景正确绘制为 1688×780，返回竖屏为 780×1688。两画布保留，暂停位置、配色和丝绸相位均保持，所采样经文完整。
- 返回竖屏后，触摸横滑从 64.053 秒到 74.053 秒，保留暂停。进度条方向键可继续定位，暂停正文与真实媒体时间一致。
- 播放中由妙法切到心经，配色在减动模式正确更新，丝绸相位连续，保留播放意图。稳定播放 5 秒内背景绘制仍为 0。由末尾自然循环到下一轮，在曲首约 13 ms 观察到循环计数为 1。
- 模拟背景 WebGL 上下文丢失，恢复后按需绘制。测试在丢失事件完整结束后请求恢复，参见 [Khronos 扩展规范](https://registry.khronos.org/webgl/extensions/WEBGL_lose_context/)。最终两个 WebGL 错误码均为 0，浏览器错误列表为空。
